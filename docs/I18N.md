# Internationalization (i18n)

## Android (primary)

| Layer | Mechanism | Location |
|-------|-----------|----------|
| **UI strings** | Android `strings.xml` + `stringResource()` | `android/app/src/main/res/values*/strings.xml` |
| **Locale override** | `AppCompatDelegate.setApplicationLocales` | Settings → Language (`LocalePreferences`) |
| **Long-form copy** | JSON in assets (onboarding, data handling) | `ui-copy/` → synced to `assets/` at build |
| **Sync / fill gaps** | `scripts/sync-android-i18n.py` | Merges base keys; `scripts/overlays/{loc}.json` for curated translations |

### Supported UI locales

`en` (default), `de`, `ar`, `ru`, `fa`, `zh-CN` (+ **System default**).

### Rules

1. **No user-visible English in Kotlin/Svelte** — use string resources or JSON copy.
2. **One locale resolver** — `LocalePreferences` for prefs + asset JSON tags.
3. **Placeholders** — keep `%1$s`, `%1$d` identical across locales.
4. **Product terms** — “Mycena”, “Relay”, “QR”, “BLE”, “Wi‑Fi” may stay untranslated where clearer.
5. **After adding keys** — run `python3 scripts/sync-android-i18n.py`. Prefer hand-written overlays in `scripts/overlays/de.json` (etc.); optional `deep_translator` fills remaining gaps when installed and online.

### Language setting

Settings → **Language** (top of Identity section). Stored in `settings.language`; applied on launch in `MycenaApplication`.

## Desktop

UI copy is English-only today. Shared JSON for onboarding/data-handling lives in `ui-copy/` and is loaded via `@onboarding-copy` / `dataHandlingCopy.js`. A future desktop locale switch should mirror `LocalePreferences` (localStorage + copy loader).

## Adding a locale

1. Add `values-xx/strings.xml` (or extend `sync-android-i18n.py` `LOCALES`).
2. Add overlay entries in `OVERLAYS` for sensitive strings.
3. Run `python3 scripts/sync-android-i18n.py`.
4. Add `ui-copy/data-handling/xx.json` (and onboarding if needed).
5. Wire asset tag in `LocalePreferences` + Settings language list.
